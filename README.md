# Flow Past a Stationary Circular Cylinder Near a Free Surface (OpenFOAM, interIsoFoam)

2D two-phase (water/air) simulation of flow past a stationary, partially/fully submerged circular cylinder beneath a free surface, using the geometric VOF solver `interIsoFoam` (isoAdvector) in OpenFOAM (ESI).

## Case description

| Parameter | Value |
|---|---|
| Dimensionality | 2D |
| Cylinder | Stationary, circular, diameter `D` = **1** |
| Reynolds number | Re = U·D/ν = **180** |
| Froude number | Fr = U/√(g·D) = **0.3** |
| Submergence depth | h/D = **0.4** (distance from cylinder top to the undisturbed free surface) |
| Phases | Water / air, free surface captured with VOF (isoAdvector) |
| Flow regime | Laminar (see `constant/turbulenceProperties`) |

> Please confirm the definitions of Re and Fr above match your setup (reference length, reference velocity, and whether depth is measured from the cylinder top).

## Validation

This setup was validated against the 2D numerical study of Reichl, Hourigan and Thompson (2005) (see References), who investigated flow past a cylinder close to a free surface at Re = 180 for Froude numbers 0.0 to 0.7 and gap ratios 0.1 to 5.0.

## How to run

1. Source your OpenFOAM environment

2. Clone the repository and go into the case folder:

3. Run the case:
 
   ./Allrun
 

`Allrun` performs the following steps:

1. `restore0Dir`: copies `0.orig` to `0`
2. `blockMesh`: generates the mesh
3. `setFields`: sets the initial water/air distribution
4. `decomposePar`: splits the domain for 4 processors
5. `mpirun -np 4 interIsoFoam -parallel`: runs the solver

If you change the number of processors, edit both `numberOfSubdomains` in `system/decomposeParDict` and the `-np` value in `Allrun`.

If `Allrun` is not executable, run `chmod +x Allrun Allclean` first.

## Important note: calculating Cd and Cl from `forces.dat`

The force output is written by the `forces` function object to `postProcessing/forces/<startTime>/forces.dat` (check `system/controlDict`). It contains **dimensional forces in N**, not coefficients, so Cd and Cl must be calculated as follows.

### 1. Non-dimensionalisation (same as Reichl et al., 2005)

```
Cd(t) = Fx(t) / (0.5 * rho_w * D * U^2)
Cl(t) = ( Fy(t) - B ) / (0.5 * rho_w * D * U^2)
```

where

- `Fx`, `Fy`: total drag (streamwise) and lift (vertical) force **per unit length** of the cylinder (pressure + viscous)
- `rho_w`: water density (`rho` of `alpha.water`, see `constant/transportProperties`)
- `D`: cylinder diameter, `U`: free-stream velocity
- `B`: constant hydrostatic (buoyancy) force per unit length for the undisturbed free-surface condition

### 2. Points to be careful about

1. **Per unit length.** A 2D OpenFOAM mesh has a finite thickness `Lz` in the z-direction (one cell thick), and the forces are computed for that thickness. Divide `Fx` and `Fy` by `Lz` before using the formulas above (or use `Aref = D * Lz` in the denominator).
2. **Buoyancy subtraction.** If the forces are computed with the total pressure `p` (the `forces` function object default), the lift includes the hydrostatic force, so `B` must be subtracted from `Fy`:
   - fully submerged cylinder: `B = rho_w * g * (pi * D^2 / 4)` per unit length
   - half-submerged cylinder: `B` is half of the value above
   - If you computed the forces with `p_rgh` (`pName p_rgh;`), the hydrostatic part is already excluded and **no** `B` should be subtracted. Check your `controlDict` and use only one approach.
3. **Density.** For multiphase solvers (`interIsoFoam`), the `forces` function object must use the local density field (`rho rho;`), not `rhoInf`.
4. **Column order.** Open `forces.dat` and read the header line. In recent ESI versions the columns are: `Time`, total force `(x y z)`, pressure force `(x y z)`, viscous force `(x y z)`, followed by moments. Older versions have no total column, so in that case use pressure + viscous.
5. **Restarts.** If you restarted the run, forces are split over several folders in `postProcessing/forces/` (e.g. `0/` and `50/`). Concatenate them in time order.
6. **Sign and axes.** The formulas assume the flow is in +x and gravity points in -y, so lift is positive upwards.

### 3. Python script

```python
import re
import numpy as np

# ---------- inputs: edit these ----------
fname = "postProcessing/forces/0/forces.dat"
rho_w = 1000.0     # water density [kg/m^3]
D     = 1.0        # cylinder diameter [m]
U     = 1.0        # free-stream velocity [m/s]
Lz    = 1.0        # mesh thickness in z [m]
g     = 9.81       # gravity [m/s^2]
submerged = True   # False for a half-submerged cylinder
use_p_rgh = False  # True if forces were computed with p_rgh (no B needed)
# ----------------------------------------

# read file (remove the parentheses used by OpenFOAM)
rows = []
with open(fname) as f:
    for line in f:
        if line.startswith("#"):
            continue
        rows.append([float(x) for x in re.sub(r"[()]", " ", line).split()])
data = np.array(rows)

t  = data[:, 0]
Fx = data[:, 1] / Lz          # total force x, per unit length
Fy = data[:, 2] / Lz          # total force y, per unit length

# buoyancy for the undisturbed free-surface condition
B = 0.0 if use_p_rgh else rho_w * g * np.pi * D**2 / 4.0
if not submerged and not use_p_rgh:
    B *= 0.5

q  = 0.5 * rho_w * D * U**2
Cd = Fx / q
Cl = (Fy - B) / q

np.savetxt("Cd_Cl.dat", np.column_stack([t, Cd, Cl]),
           header="time  Cd  Cl")

# statistics over the developed (periodic) part of the signal
t0 = 0.5 * t[-1]              # edit: discard the initial transient
m = t > t0
print("Mean Cd :", Cd[m].mean())
print("Mean Cl :", Cl[m].mean())
print("RMS  Cd':", Cd[m].std())
print("RMS  Cl':", Cl[m].std())

# Strouhal number from the dominant lift frequency
dt = np.mean(np.diff(t[m]))
cl = Cl[m] - Cl[m].mean()
freq = np.fft.rfftfreq(len(cl), dt)
f_peak = freq[np.argmax(np.abs(np.fft.rfft(cl)))]
print("St      :", f_peak * D / U)
```

Run it from the case folder after the simulation: `python3 calc_coeffs.py` (save the script under that name).

Note: if the time step is not constant, interpolate onto a uniform time grid (`np.interp`) before the FFT.

### 4. Using `forceCoeffs` instead

OpenFOAM's `forceCoeffs` function object also writes `Cd` and `Cl` directly (`postProcessing/forceCoeffs/.../coefficient.dat`), using `magUInf`, `lRef` and `Aref` from the dictionary. It does **not** subtract buoyancy, so for this free-surface case `Cl` from `forceCoeffs` must be corrected with `B` as described above.
